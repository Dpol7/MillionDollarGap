8. ESTIMATED TIME CALCULATION
==================================================

This is extremely important.

DO NOT simply calculate:

blocks remaining × 10 minutes

and present the result as a precise date.

Bitcoin blocks are not produced exactly every 10 minutes.

The website should use actual recent Bitcoin block production data.

Use a configurable recent-block lookback.

Default:

2,016 blocks

Calculate:

- average block interval
- median block interval
- variance / distribution of recent block intervals

Use the actual recent block data to estimate future block timing.

The system should produce:

1. Most likely estimated date
2. 50% probability range
3. 80% probability range

Example:

BLOCK #1,234,567

Most likely:
July 2033

50% likely:
June–August 2033

80% likely:
April–November 2033

Important:

This is an ESTIMATE, not a guarantee.

Display:

"Estimated from recent Bitcoin block production. Actual timing will vary."

==================================================
9. PROBABILISTIC TIME MODEL
==================================================

Implement the time estimate using a transparent statistical model.

For future blocks, model future block intervals using recent observed Bitcoin block-time data.

A reasonable first implementation:

- retrieve the most recent 2,016 actual block intervals
- calculate the empirical distribution
- simulate or statistically estimate cumulative time to the selected future block
- calculate the median / most likely estimate
- calculate the 25th/75th percentile for the 50% range
- calculate the 10th/90th percentile for the 80% range

The backend should perform this calculation rather than the browser doing expensive calculations.

Cache the result.

Recalculate when:

- current block height changes materially
- a new block data batch is available
- the user selects a substantially different future block

The model should be configurable.

Create a settings/config object for:

LOOKBACK_BLOCKS = 2016

so this can be changed later.

IMPORTANT:

Because Bitcoin difficulty adjusts every 2016 blocks and future hash rate can change, do not claim this statistical model perfectly predicts future block timing.

The UI should describe it as an estimate.
